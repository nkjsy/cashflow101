# 大规模自动对局测试指南

> 适用范围：现金流实验室单机规则核心、基础 AI 和游戏平衡。

批量模拟器不启动 React 或浏览器，而是让自动策略持续向正式 `game-core` 提交 `GameCommand`。它适合发现随机序列下的状态机错误、财务不一致、命令死锁和异常长局，也适合比较规则或卡牌数值调整前后的游戏节奏。

## 1. 准备环境

在 PowerShell 中进入 Web 项目并安装依赖：

```powershell
cd C:\Users\SJ\game\web
npm install
```

确认模拟脚本可用：

```powershell
npm run simulate -- --games 20 --max-rounds 100 --seed 1 --ai 3
```

参数前的独立 `--` 不能省略；它负责把后续参数传给模拟器，而不是 npm。

## 2. 推荐测试层级

### 2.1 提交前回归

```powershell
npm test
```

完整 Vitest 中包含 500 局固定种子的平衡回归，当前门槛为：

- 100 轮内完成率至少 `95%`。
- 完成局中位轮数不超过 `50`。
- 完成局 P90 不超过 `70`。
- 首次进入快车道中位轮数不超过 `28`。
- 首次进入快车道 P90 不超过 `45`。
- 胜者快车道停留中位数为 `9–13` 轮。
- 四人局快车道中位数应为 Rat Race 首次出圈中位数的 `40%–65%`。
- 不允许状态不变量失败或命令死锁。

只运行批量模拟测试：

```powershell
npm test -- src/simulation/simulator.test.ts
```

### 2.2 日常平衡检查

```powershell
npm run simulate -- --games 1000 --max-rounds 100 --seed 1 --ai 3
```

1,000 局通常足以快速发现明显的节奏回退或职业胜率偏移。比较两次改动时必须使用完全相同的参数。

### 2.3 大样本压力测试

```powershell
npm run simulate -- --games 10000 --max-rounds 100 --seed 1 --ai 3
```

适合修改以下内容后运行：

- 机会、市场、快车道卡牌数值。
- 职业收入或支出。
- AI 买入、卖出、借款或慈善策略。
- 棋盘格分布、骰子规则或 Payday 结算。
- 破产、跳过回合、进入快车道和胜利条件。

当前机器上的 10,000 局参考结果：

```text
完成率：100.0%（10000/10000）
完成局轮数：中位数 20，P90 30
首次进入快车道：中位数 14，P90 23
胜者快车道停留：中位数 5，P90 9
进入快车道 1 轮内获胜：0.0%
有玩家进入快车道的对局：100.0%
发生破产的对局：1.2%，平均每局 0.01 人
平均命令数：244.2
资产购买量：房地产 45755、企业 67276、股票 2461、基金 5793、存单 3687
交易购买量：小生意 96818、大买卖 28154
耗时：约 5.5 秒
```

这些数字是电子原型的平衡基线，不是官方桌游指标。

模拟器与浏览器共用同一个纯策略模块。标准难度下，均衡 AI 保留至少半个月总支出，优先购买月现金回报达到 8% 的经营资产；保守、进取性格会分别提高或降低储备、回报门槛、借款上限和市场止损线。专家难度会在对手进入快车道后适度加速投资，并在快车道为所选梦想预留现金。证券仍使用独立规则：低价股票要求充足储备；指数基金月回报至少 2%、存单至少 2.5%，三类证券都不借款购买。只有扣除性格对应储备后仍能支付最低大买卖首付时才选择 Big Deal。

2026-07 泛类市场报价改为随资产权益缩放后的 1,000 局四人标准难度冒烟基线：完成率 100%，完成轮数中位数 25、P90 33，首次进入快车道中位数 19，破产对局比例 1.4%，平均命令数 313.7。该样本用于快速回归；正式平衡比较仍应使用 10,000 局命令。旧存档保留历史固定报价规则以保证命令回放一致，新游戏才使用缩放报价。

2026-07 原 `income-scaled` 快车道使用 `24 ×` 梦想价格和 `$8,000–$15,000` 企业收入；旧存档继续保留这些数值。当前 `accelerated` 新局改为 `12 ×` 梦想价格和 `$14,000–$24,000` 企业收入，任何单笔企业仍低于 `$50,000` 胜利线。30,000 局跨规模结果为：四人 Rat Race/快车道中位数 `20/11`，三人 `24/11`，双人 `29/12`；完成率均为 100%，一轮内快车道胜率均为 0%。

2026-07 全局职业平衡 `global-v2` 将初始储蓄收敛到约 `0.8–0.86` 个月基础支出，并按职业生活成本缩放 Doodad。在当前加速快车道下，四人局职业胜率为 `22.8%–27.5%`，三人局 `29.8%–36.4%`，双人局 `46.9%–53.1%`，均在实用验收区间内。旧存档使用 `legacy` 财务规则。

### 2.4 玩家数量矩阵

分别测试 1–3 名 AI：

```powershell
1..3 | ForEach-Object {
  npm run simulate -- --games 3000 --max-rounds 100 --seed 1 --ai $_
}
```

玩家数量会改变市场响应、轮数统计和胜者分布，不应只测四人局。

## 3. 命令参数

| 参数 | 默认值 | 含义 |
| --- | ---: | --- |
| `--games` | `1000` | 连续模拟的对局数量 |
| `--max-rounds` | `150` | 单局轮数上限，超过后记为未完成 |
| `--seed` | `1` | 第一局的随机种子，后续每局依次加 1 |
| `--ai` | `3` | AI 数量，只允许 `1`、`2` 或 `3` |

例如：

```powershell
npm run simulate -- --games 5000 --max-rounds 80 --seed 20000 --ai 2
```

这会运行种子 `20000` 到 `24999`，每局一名自动玩家加两名 AI，最多 80 轮。

## 4. 如何解读结果

### 完成率

在轮数上限内产生胜者的对局比例。完成率下降通常意味着：

- 老鼠赛跑圈资产现金流不足。
- AI 现金储备条件过于保守。
- 市场频繁卖掉关键资产。
- 快车道企业过贵或现金流增量过低。
- 某个状态机分支不能自然结束。

### 中位数与 P90

中位数代表典型游戏时长，P90 代表长尾。中位数稳定但 P90 明显上升，通常说明少数随机路径、职业或市场组合会产生异常长局。

### 首次进入快车道

比“产生胜者”更直接地衡量老鼠赛跑圈节奏。当前目标是中位数不超过 28 轮、P90 不超过 45 轮。完成局很快但首次出圈很慢，通常表示快车道过短，不能说明前半局体验良好。

### 胜者快车道停留

按胜者实际经历的快车道掷骰回合计数，不使用可能受破产跳过影响的全局轮数。当前参考值为中位数 4、P90 6，并要求进入快车道 1 轮内通过企业或梦想获胜的比例为 0%。

### 破产率

报告同时输出发生过破产的对局比例和平均每局破产人数。自动策略会先选择不导致负月现金流的贷款，贷款不可持续时再清算资产，最后宣布破产；市场报价低于成本时通常拒绝，只有现金低于四分之一月支出才会为流动性止损。当前四人局参考值约为 0.8%；严格降至 0% 仍需检查无限续借或破产路径失效，明显升高则表示负面事件或现金储备过于严苛。

### 平均命令数

近似反映规则引擎工作量和每局决策数量。轮数不变但命令数骤增，可能出现重复决策、多人市场响应膨胀或无效循环。

### 截止时仍在老鼠赛跑圈的玩家数

只统计未完成局。该值较高时，应优先检查出圈所需被动收入、机会牌现金流和资产被市场出售的频率。

### 职业胜局

CLI 同时输出职业实际参赛次数、胜率、95% Wilson 区间、出圈率、平均首次出圈轮数和破产率。应比较职业胜率与同局公平基线 `$1 / 玩家数`，不能只比较原始胜局数；职业本来可以有难度差异，因此不要求绝对均匀，但改动前后出现剧烈变化时必须调查。当前 200,000 局专项结果见[职业平衡大规模测试报告](profession-balance-report.md)。

### 资产与交易购买量

报告按房地产、企业、股票、基金和存单统计实际购买次数，并区分 Small Deal 与 Big Deal。计数发生在购买命令执行前，因此资产后来被 Market 卖出也不会丢失。某类长期为 0 通常意味着基础 AI 的现金储备或回报门槛不会选择它，不代表真人玩家无法购买。

### 未完成示例种子

报告最多列出 10 个达到轮数上限仍未结束的种子。它们是排查长局的第一入口。

## 5. 复现失败或长局

假设输出包含：

```text
未完成示例种子：2345, 2418
```

只重放第一局：

```powershell
npm run simulate -- --games 1 --max-rounds 100 --seed 2345 --ai 3
```

如果模拟器发现非法命令或状态不变量失败，错误消息会包含：

```text
Seed 2345, revision 127: ...
```

使用同一个 `seed`、`max-rounds` 和 `ai` 参数可以重现相同骰子、卡牌与命令序列。`revision` 用于定位失败发生在第几次状态变更附近。

需要调试单一种子时，可以在 `simulateGame` 的命令执行处临时记录 `command` 和 `state.logs`；不要改变随机调用次数，否则后续序列会变化。

## 6. 修改平衡时的标准流程

1. 保存改动前基线：

```powershell
npm run simulate -- --games 10000 --max-rounds 100 --seed 1 --ai 3
```

2. 修改卡牌、职业、棋盘或 AI 策略。
3. 使用完全相同的参数再次运行。
4. 对比完成率、首次出圈轮数、中位数、P90、破产率、平均命令数和职业胜局。
5. 重放新出现的未完成种子。
6. 运行完整验证：

```powershell
npm test
npm run test:e2e
npm run build
npm run lint
```

不要只看平均轮数。平均值容易被少量极端长局扭曲，中位数和 P90 更适合判断典型节奏与长尾。

## 7. 自动检查了什么

模拟器每条命令后检查：

- `currentPlayerIndex` 必须指向现有玩家。
- 待决策玩家必须存在。
- 现金、收入、支出和目标不能是 `NaN` 或无限值。
- 银行贷款、孩子数量和被动收入不能越界。
- 被动收入必须等于持有资产现金流合计。
- 证券数量必须大于 0，单位成本必须是有限的非负数。
- 每条成功命令必须推进 `revision`。
- 命令必须被规则引擎接受。
- 单局命令数量不能超过防死锁上限。

实现位置：

- `web/src/simulation/simulator.ts`：自动策略、状态不变量和汇总统计。
- `web/src/simulation/cli.ts`：命令行参数和报告输出。
- `web/src/simulation/simulator.test.ts`：500 局 CI 平衡门槛。

## 8. 当前覆盖边界

批量模拟不能代替其他测试：

- 自动策略是固定的基础策略，不代表真实玩家的谈判、风险偏好或学习过程。
- 自动策略在资不抵债时依次选择可持续贷款、资产清算和破产，但不会模拟真人提前放弃或不同风险偏好；破产率仍需结合真人试玩解读。
- 它不检查 React 渲染、按钮可点击性、响应式布局和浏览器存档；这些由组件测试和 Playwright 负责。
- 它不模拟网络延迟、断线重连和多人并发。
- 高完成率只能说明当前自动策略能结束游戏，不能单独证明游戏一定有趣或规则完全正确。

因此应同时保留规则单元测试、状态机测试、批量模拟、组件测试和浏览器 E2E。
